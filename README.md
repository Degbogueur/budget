# Budget

A personal expense tracker built with **ASP.NET Core 10** and **React 19**.
Sign up, record your expenses, organize them with built-in or custom categories, and see where your money goes each month.

## Features

- **Accounts** – register, sign in and sign out. Authentication uses an HttpOnly cookie, so no token is ever stored in JavaScript.
- **Expenses** – add an expense with a description, an amount, a category and a date, or delete it.
- **Categories** – six built-in categories (Food, Housing, Transport, Leisure, Health, Other). If none fits, create your own without leaving the expense form; it is selected right away.
- **Monthly view** – browse expenses month by month and filter them by category.
- **Monthly summary** – total spent, number of expenses and a breakdown by category.
- **Privacy** – each user only sees their own expenses and custom categories.
- **Clear validation errors** – the API returns field-level errors that the UI displays under the matching input.

## Architecture

```text
            development

 Browser ──► Vite dev server ──/api──► ASP.NET Core API ──► SQLite
             localhost:5173   (proxy)  localhost:5054       budget.db
```

- In development, Vite forwards every `/api` request to the API. The browser only talks to one origin, so there is **no CORS configuration** and the authentication cookie works as is.
- The API is a single project organized by folders: `Domain` (entities and rules), `Data` (EF Core), `Features` (endpoints grouped by feature) and `ErrorHandling`.
- Business rules live **inside the entities** (rich domain model). Endpoints use the `DbContext` directly; there is no repository layer.
- Reads are projected to DTOs with `AsNoTracking`; writes go through entity methods.

## Domain model and business rules

### Expense

| Property | Type | Rule |
|---|---|---|
| `Id` | `int` | Generated by the database |
| `UserId` | `string` | Owner; users never see each other's expenses |
| `Description` | `string` | 2 to 100 characters, trimmed |
| `Amount` | `decimal` | Greater than 0, at most 100,000, at most 2 decimal places |
| `CategoryId` | `int` | Must reference a category visible to the owner |
| `Date` | `DateOnly` | Cannot be in the future |

### Category

| Property | Type | Rule |
|---|---|---|
| `Id` | `int` | Generated by the database (built-in categories use ids 1 to 6) |
| `UserId` | `string?` | `null` for built-in categories, otherwise the user who created it |
| `Name` | `string` | 2 to 30 characters, trimmed, unique per user (case-insensitive) |

- Built-in categories are shared by everyone and inserted by the initial migration.
- Custom categories are private: another user can neither see nor use them (the API answers `Unknown category.`).

## API reference

All routes are under `/api`. JSON uses camelCase. Every route except `register` and `login` requires authentication.

| Method | Route | Body | Response |
|---|---|---|---|
| `POST` | `/api/auth/register` | `{ email, password }` | `200`, `400` |
| `POST` | `/api/auth/login?useCookies=true` | `{ email, password }` | `200` + cookie, `401` |
| `POST` | `/api/auth/logout` | – | `204` |
| `GET` | `/api/auth/me` | – | `200 { email }`, `401` |
| `GET` | `/api/categories` | – | `200 [{ id, name, isCustom }]` |
| `POST` | `/api/categories` | `{ name }` | `201`, `400` |
| `GET` | `/api/expenses?month=2026-11&categoryId=4` | – | `200 [Expense]` |
| `GET` | `/api/expenses/summary?month=2026-11` | – | `200 { month, total, count, byCategory }` |
| `GET` | `/api/expenses/{id}` | – | `200`, `404` |
| `POST` | `/api/expenses` | `{ description, amount, categoryId, date? }` | `201`, `400` |
| `PUT` | `/api/expenses/{id}` | same as `POST` | `204`, `400`, `404` |
| `DELETE` | `/api/expenses/{id}` | – | `204`, `404` |

`month` defaults to the current month and `date` defaults to today.

### Error format

A business-rule violation returns `400` with a ValidationProblem body. Each key in `errors` is the property at fault, which the front end uses to show the message under the right field:

```json
{
  "title": "A business rule was violated.",
  "status": 400,
  "errors": { "Amount": ["Amount must be greater than 0."] }
}
```

An expense that belongs to another user returns `404` rather than `403`, so the API never reveals that it exists.

## Getting started

### Prerequisites

- [.NET 10 SDK](https://dotnet.microsoft.com/download)
- [Node.js 24 LTS](https://nodejs.org/) (includes npm)
- The EF Core CLI, only if you need to create migrations: `dotnet tool install --global dotnet-ef`

### 1. Clone the repository

```bash
git clone https://github.com/<your-account>/budget.git
cd budget
```

### 2. Run the API

```bash
dotnet run --project src/Budget.Api
```

- The API listens on `http://localhost:5054`.
- On startup, migrations are applied automatically: `src/Budget.Api/budget.db` is created with the built-in categories.
- The interactive API documentation is available at `http://localhost:5054/scalar` (development only).

### 3. Run the front end

In a second terminal:

```bash
cd web
npm install
npm run dev
```

Open `http://localhost:5173`, create an account, then sign in.

### Front-end scripts

| Command | Purpose |
|---|---|
| `npm run dev` | Start the Vite dev server with the `/api` proxy |
| `npm run build` | Type-check and build to `web/dist` |
| `npm run lint` | Run oxlint |
| `npm test` | Run Vitest in watch mode (`npx vitest run` for a single run) |
| `npm run preview` | Serve the production build locally |

## Running the tests

### API

```bash
dotnet test
```

- **Unit tests** (`tests/Budget.Api.Tests/Domain`) check the entity rules: validation of descriptions, amounts, dates, category names and category visibility.
- **Integration tests** (`tests/Budget.Api.Tests/Api`) start the whole API in memory with `WebApplicationFactory` and a throwaway SQLite file. They cover authentication (401), creating and listing expenses, validation errors, custom categories and their privacy between users.

### Front end

```bash
cd web
npx vitest run
```

Component tests use Testing Library with jsdom.

## Database and migrations

- The connection string is `ConnectionStrings:Budget` in `src/Budget.Api/appsettings.json` (`Data Source=budget.db` by default).
- It can be overridden with the environment variable `ConnectionStrings__Budget`.
- After changing the model, add a migration; it is applied at the next startup:

```bash
dotnet ef migrations add <MigrationName> --project src/Budget.Api
```

- To start over with an empty database, stop the API and delete `src/Budget.Api/budget.db`.

> SQLite cannot sort or sum `decimal` columns in SQL. Expenses are therefore sorted by date, and the monthly totals are computed in memory after a projection.

## Design decisions

| Decision | Choice | Why |
|---|---|---|
| API organization | One project, folders by concern and by feature | Simple and quick to navigate |
| Business logic | In the `Expense` and `Category` entities | One source of truth; an invalid object cannot be created |
| Data access | `DbContext` in the endpoints, no repository | `DbContext` already is a unit of work and a set of repositories |
| Reads / writes | DTO projections for reads, entity methods for writes | The spirit of CQRS without the ceremony (no MediatR) |
| Database | SQLite | No server to run, same behavior on every machine |
| Authentication | Identity with an HttpOnly cookie | Nothing sensitive is reachable from JavaScript |
| Server state | TanStack Query | Caching, loading states and cache invalidation after mutations |
| Language | English everywhere (UI, API messages, code, commits) | Professional convention; localization comes later |
